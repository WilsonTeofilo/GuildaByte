GUILDABYTE - MISSOES DE ARQUITETURA

Objetivo:
Construir a GuildaByte por missoes pequenas, testaveis e seguras.
Nada de monolito baguncado. Nada de regra importante no front-end.

PRINCIPIOS OBRIGATORIOS

1. Front-end impecavel, mas nunca soberano
O front-end precisa ser bonito, polido, responsivo, claro e profissional.
Mas front-end nao decide preco, permissao, comissao, status financeiro, limite, desconto, aceite ou regra sensivel.

Regra:
Todo dado importante vem do backend.
Todo calculo importante acontece no backend.
Toda permissao e validada no backend.
Todo valor financeiro e recalculado/conferido no backend.
Todo input do usuario e tratado como suspeito.

2. Backend como fonte da verdade
O navegador pode mostrar, sugerir, filtrar e melhorar experiencia.
Mas quem valida e confirma e sempre o servidor.

3. Anti monolito
Separar:
- interface
- controller
- caso de uso
- regra de dominio
- repositorio/banco
- integracao externa

4. Codigo legado compreensivel
Uma pessoa nova deve abrir o projeto e entender:
- onde fica tela
- onde fica regra
- onde fica banco
- onde fica configuracao
- onde fica seguranca
- onde fica integracao

5. GitHub blindado
Nunca commitar:
- .env
- token
- chave privada
- dump real
- arquivo real de cliente
- backup real
- credencial
